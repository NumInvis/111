# 纯文字 UX 与交互指南

## 1. 体验目标

界面必须让评审快速理解三件事：这是一个完整游戏、世界由 AI 生成、玩家行为会改变故事。

首版 UX 优先级：

- 快速开始。
- 明确当前目标。
- 明确可点击行动。
- 明确 AI 正在生成或裁决。
- 明确状态变化和结局证据。

## 2. 文字游戏界面原则

这是纯文字游戏，不引入主视觉、角色原画、场景图、配音、音乐、视频增强或其他美术音频资产。UI 只服务于阅读、选择、对话、状态理解和结局复盘。

核心规则：

- 信息层级清晰：当前年份、地点、境界、目标、可选行动必须一眼可见。
- 文本可读性优先：正文行宽、段落间距和字号优先于装饰。
- 状态变化显性化：每次行动后的属性、关系、记忆和风险变化必须明确展示。
- AI 生成过程透明：生成中、校验中、裁决中、回退 Mock 必须有文本提示。
- 不依赖图片表达关键信息：所有剧情、地图、NPC、证据和结局都必须以文字可理解。
- 保留少量高对比 UI 样式：按钮、面板、标签可以使用粗边框和高对比色，但不得把视觉资产作为交付重点。

## 3. 文字组件规范

### 3.1 行动按钮

- 文案使用动词开头，例如“调查石碑”“询问长老”“下一年”。
- 每个按钮必须有明确结果预期或风险提示。
- 不允许出现“继续”“确定”这类无法判断含义的关键行动按钮。

### 3.2 事件卡片

- 包含事件标题、时间、地点、正文、2-3 个选项。
- 每个选项包含短标签、描述和风险等级。
- 选项必须有真实权衡，不能全优或全劣。

### 3.3 状态面板

- 展示年龄、寿元、境界、属性、当前位置、关键关系。
- 状态变化使用 `+/-` 和原因说明。
- 隐藏骰子和内部权重不直接展示，只展示叙事化结果。

### 3.4 NPC 对话块

- 展示 NPC 名称、境界、势力、情绪、信任度。
- 对话正文支持流式输出。
- 记忆引用以文字标签展示，例如“引用记忆：你曾归还他的密卷”。

### 3.5 旅记条目

- 每条包含时间、地点、行动、结果、证据标签。
- 关键证据可被结局系统引用。
- 旅记不是纯日志，要形成可读的人生传记。

## 4. 页面体验要求

### 首页

- 一句话说明游戏。
- “生成世界”主按钮。
- “继续游戏”次按钮。
- 展示 AI 世界、AI NPC、涌现叙事三段文字说明。

### 世界生成页

- 偏好选择：纯粹数学、应用数学、计算数学、统计概率、随机混沌。
- 模式选择：快速模式、完整模式、无限模式。
- seed 输入。
- 生成中展示步骤：世界规则、势力、地点、NPC、事件、安全检查。

### 探索页

- 左侧或顶部显示文字节点列表。
- 主区域显示地点描述和行动按钮。
- 侧栏显示 NPC、传闻和状态标签。
- 行动后必须展示状态变化。

### 对话页

- NPC 境界、势力、情绪、信任度。
- 对话流式输出。
- 显示“引用记忆”标签，证明不是一次性聊天。

### 旅记页

- 时间线展示行动和事件。
- 因果碎片用贴纸标签展示。
- 结局证据高亮。

### 结局页

- 大标题展示结局类型。
- AI 生成一生总结。
- 展示触发证据和状态数据。
- 提供重开入口。

## 5. 文本质量标准

- 每个事件正文 80-180 字，足够形成情境但不拖慢节奏。
- 每个选项 12-28 字，清晰表达选择方向。
- NPC 回复 80-220 字，必须体现人设、当前关系和上下文。
- 旅记条目 50-120 字，突出行动、后果和证据。
- 结局总结 300-800 字，包含一生轨迹、关键选择、最终境界和遗憾或成就。

## 6. 文字交互验收标准

- 无任何视觉、音频、视频资产依赖时，游戏仍可完整体验。
- 玩家只通过文字阅读、点击选择和自由输入完成游戏。
- 每个页面都有明确当前状态、可行动项和下一步目标。
- AI 生成文本可被 schema 校验、状态裁决和旅记引用。
- 结局页能用文字解释“为什么会走到这个结局”。
